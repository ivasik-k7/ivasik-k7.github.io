Method
Everything measured on a production build (React 19.2.8 prod bundle, verified via bundleType), served by vite preview and driven over CDP. Because ?scene=/window.__game are DEV-gated, I built an out-of-tree copy in the scratchpad with exactly two lines changed (EngineGame.tsx dev-params guard + onReady) — the repo itself was not modified. Pre-boot instrumentation: React DevTools hook for commit counts, wrappers on setInterval/setTimeout/rAF/addEventListener, MutationObserver on #root, long-animation-frame observer, a build with render counters compiled in, and a wrapped offsetWidth getter. Two fixes were built and A/B measured.

A. Findings (numbered as in the report)
1. Boot: ~1.8 s of sprite-rig construction blocks first paint — CRITICAL. In-page performance.now() inside the builders, same run, minified prod: createAnimal (5 calls) 1,433 ms, createNpc (18 calls) 376 ms, inside a 2,009 ms module-eval long animation frame — 90% of the pre-paint freeze (91%/92% on two repeats). 1,125 sprite frames / 1,078,896 cells built on every load. The forcing mechanism is two module-scope enumerations: npcs.ts:481 NPC_LIST = Object.values(NPCS), consumed by nothing but the dev-only NpcStudio, and NpcStudio.tsx:248 KENNEL = Object.values(ANIMALS) — and EngineGame.tsx:27 imports NpcStudio statically. Opening the game needs 1 animal and 1 NPC. FCP measured 2.8–4.9 s.

2. District mounts 7,785 hidden <rect>s — one actor's whole sprite sheet — HIGH. GameRuntime.tsx:2345 mounts every frame of every runtime actor as display:none groups. District: 9,377 DOM nodes / 8,552 rects, 7,605 inside hidden groups; every other scene has 0. Scene-entry blocking: district 724–1,031 ms vs 168–346 ms everywhere else. A/B built: mounting only idleFrame + walkCycle (the only frames the runtime can show — actor.step is unused game-wide, so this is behaviour-identical) gives DOM −75%, rects −81%, entry frame 1,031 → 220 ms.

3. Per-NPC setInterval + useState rebuilds ~1,000–1,600 <rect> React elements per second, permanently — HIGH. Standing still: gym 13.3 NpcActor renders/s → 1,459 rects/s, district 8.3 → 1,381, outside 5.5 → 904; commits 23–32/s vs 1.3/s in the studio (no NPCs). DOM churn: gym 1,688 mutations/s, 576 insertions + 579 removals per second. PixelSprite's y:runStart keys mean shifted runs are destroyed and recreated rather than updated.

4. NPCs and monologues run full-rate behind a full-screen menu — MEDIUM. Menu open in outside: 26.8–30.6 commits/s, 851 rects/s, 328 mutations/s. The rAF loop throttles; the intervals don't. NpcActor already has a playing prop.

5. NpcMonologue types per-character and forces a layout on each character — MEDIUM-HIGH. NpcMonologue.tsx:154 + :172 (offsetWidth in a useLayoutEffect keyed on shown). Idle, 20 s: outside 195 forced layouts, 346 ms (17.3 ms/s); district 149, 853 ms (42.6 ms/s, 5.7 ms each) because its DOM is 9,400 nodes. With fix 2 applied, district's drops to 430 ms — findings 2 and 5 compound.

6. Dev studios in the main chunk; ?npcs is the un-fixed twin of PlayerStudio. ?npcs: 102 PixelSprite renders/s, 17,132 rects/s, 9,498 DOM nodes, 43 intervals, worst frame 450 ms. ?player is confirmed fixed (94 canvases). Note a correction I verified: React.lazy-ing both studios makes the build look like 929 → 589 KB, but rolldown just moves the 311.8 KB NPC/animal data to a shared chunk that is still a static import; the real eager-byte win is only −29.7 KB (−3%).

7. The eager 928 KB chunk — the bytes are not the problem. 274.6 KB gzip, fetched in 41 ms; DCL 303–471 ms. Coverage: 341 KB of 906 KB (37.7%) executes at boot. The freeze starts after the bytes land. Code-splitting scenes is not the lever; lazy rig construction is.

8. 21–74% of every wide scene's live elements are off camera (parking 74%, district 69%, gym 60%, outside 57%), and CullBox/CullStrip still have no callers although the band store is published.

9. Input latency: keydown 216–232 ms while advancing dialogue rapidly (processing only 10–25 ms — the rest is failing to paint), with 2,350 mutations/s in that window.

10. Geist and Archivo webfonts are declared and never applied — 8 woff2 files (~157 KB) in dist that can never be requested. 11. NPC_BY_OBJECT, ANIMAL_LIST, ANIMAL_BY_OBJECT have zero consumers. Plus six duplicate matchMedia reduced-motion hooks (one MediaQueryList per NPC) where runtime-perf.ts:554 already exports a shared one.

B. Top fixes
P1 Lazy the two dev studios + build rigs on first access + delete the four dead exports (~80 lines, 4 files) → target −1.5 s of pre-paint block. Risk medium; my quick end-to-end A/B was inconclusive on a noisy machine — the composition measurement is solid, re-verify the delta. P1b createAnimal is 287 ms/animal vs 21 ms/NPC — worth profiling regardless. P2 Filter actor frames to idleFrame + walkCycle, or rasterize actors through the existing AtlasSprite (1 line / ~40 lines) → measured district DOM −75%, entry frame −79%. P3 Move NPC frame advance off React onto the atlas/rAF path the player already uses (~120 lines) → idle commits 23–32/s → ~1/s, ~1,500 rect allocations/s → 0. P4 Fix the monologue typewriter (~30 lines, one file). P5 Pass overlay state into the existing playing prop (~25 lines). Then P6 NpcStudio canvases, P7 adopt CullBox, P8 drop the two fonts, P9 collapse the reduced-motion hooks.

C. Already good
No leaks under stress — 8 rounds of 6 dialogue cycles + 4 menu cycles + 12 travels + walking (96 travels, 48 dialogues, 32 menus), GC'd before each sample: heap 22.2 → 26.7 MB then flat; DOM nodes flat 2,794; listeners flat 328; intervals flat 6; timeouts flat 2. Rapid travel (8 in 2 s) settles back to a cold-arrival profile. paletteForAppearanceCached is a WeakMap on the appearance object — bounded, not a growing cache. The refs-over-state design works: GameRuntime re-renders 0/s standing, 1.2–3.5/s walking; EngineGame 0/s during play — so the inline RuntimeConfig never cascades. artKey gating, paletteKey pinning, domCache write-skipping, promote(), the owned Timers, the fx pool, and the actor off-camera bounds check are all real and working. PlayerStudio and the DialogueBox typewriter are confirmed fixed.

One note: the working tree kept changing during the audit (NpcMonologue.tsx and CharacterMonologue.tsx were edited after my 11:44 snapshot). All cited line numbers were re-verified at the end and still hold, but finding 5 / fix P4 should be re-checked against current code.
